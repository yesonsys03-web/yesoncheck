# YesonCheck 리팩터링 가이드

## 소개
YesonCheck는 PyQt5 기반의 영상 비교/검토 툴입니다. 이번 리팩터링으로 코드가 패키지 구조(`yesoncheck/`)로 재정비되어 유지보수가 쉬워졌으며, 기능과 UI는 기존 버전과 동일하게 동작합니다.

## 준비 사항
- Python 3.10 (권장: `./setup_build_env.sh`가 만드는 `~/coding/p310_tf` 가상환경 — TensorFlow 포함. TF 이전의 `~/coding/p310`은 빌드에 쓰지 않음)
- 시스템에 설치된 FFmpeg 6.x 이상 (`ffmpeg`, `ffprobe` 명령어가 PATH에서 동작해야 함)
- pip 최신 버전: `python -m pip install --upgrade pip`
- **Windows에서 소리를 들으려면 [K-Lite Codec Pack](https://codecguide.com/download_kl.htm) (Basic판이면 충분)** — YesonCheck의 소리는 Windows의 DirectShow로 재생하는데, DirectShow는 mp4·mov 파일을 혼자 열지 못합니다(K-Lite에 든 LAV 필터가 엶). 없으면 화면은 나오지만 소리가 나지 않습니다. 새 PC에는 YesonCheck와 함께 설치하세요. Mac은 필요 없습니다.

### 필수 파이썬 패키지
`./setup_build_env.sh`가 아래 패키지를 `requirements-build.txt`의 고정 버전으로 설치합니다 ([BUILD.md](BUILD.md)).
(paddleocr 2.7.3 때문에 opencv는 4.6.0.66. paddlepaddle은 Mac(Intel·Apple Silicon) 3.0.0, Windows 2.6.2를 씁니다.)
- `PyQt5` : 데스크톱 UI 프레임워크
- `opencv-python` : 프레임 단위 이미지/영상 처리
- `numpy` : 배열 연산 및 영상 버퍼 처리
- `pyinstaller` : macOS 앱 번들 패키징 시 사용 (개발 모드 실행만 필요하다면 생략 가능)
- `paddlepaddle`, `paddleocr` : ROI 영역 글자 인식을 위한 PaddleOCR 엔진 (macOS의 경우 [Paddle 공식 안내](https://www.paddlepaddle.org.cn/install/quick)와 같이 OS별 설치 옵션을 참고하세요.)
- `tensorflow` 2.15.1 : 애니매틱2(TransNetV2 딥러닝 컷 감지). TransNetV2 코드(`yesoncheck/transnetv2_model.py`)와
  가중치(`vendor/transnetv2-weights/`)는 저장소에 들어 있어 pip로 따로 설치하지 않습니다. x86에서는 CPU가 AVX를 지원해야 합니다.

## 실행 방법

### 원클릭 실행 (권장)
명령어 복사 없이 한 번에 실행·빌드할 수 있습니다.

| 동작 | 방법 |
|------|------|
| **앱 실행** | 터미널에서 `./run_app.sh` 실행 (또는 앱 메뉴 **Help → 실행 및 빌드** → **▶ 앱 실행**) |
| **macOS 앱 빌드** | 터미널에서 `./build_app.sh` 실행 (또는 **Help → 실행 및 빌드** → **📦 macOS 앱 빌드**) |

- `run_app.sh`, `build_app.sh`는 프로젝트 루트에 있으며, `~/coding/p310_tf` 가상환경을 사용합니다.
- 앱이 떠 있는 상태에서는 **Help → 실행 및 빌드**에서 위 버튼을 누르면 새 터미널에서 실행/빌드됩니다.

### 수동 실행 (가상환경·명령어 직접 사용 시)
1. 가상환경 생성·의존성 설치 (최초 한 번)  
   ```bash
   ./setup_build_env.sh
   ```
2. 가상환경 활성화  
   ```bash
   source ~/coding/p310_tf/bin/activate
   ```
3. 애플리케이션 실행  
   ```bash
   python -m yesoncheck.app
   ```
   첫 실행 시 폰트/스타일 경고가 출력될 수 있으나 기능에는 영향이 없습니다.

## OCR 기반 구간 추출
1. Video A를 로드하여 프레임이 표시된 상태로 둡니다.
2. 사이드 컨트롤의 `OCR ROI 지정` 버튼을 눌러 비디오 위에서 분석할 영역을 드래그합니다.
3. ROI가 지정되면 `OCR 구간 추출` 버튼이 활성화됩니다. 클릭하면 전체 프레임을 분석한 뒤 결과 검토 다이얼로그가 열립니다.
4. 다이얼로그에서 X-Sheet 형태의 표와 타임라인을 통해 구간을 확인·수정한 뒤 `내보내기`를 누르면 저장 폴더를 선택하고 FFmpeg로 개별 클립이 `libx264`로 인코딩됩니다.
5. 진행 상황과 메시지는 컨트롤 패널 하단의 상태 라벨로 확인할 수 있으며, 취소 버튼을 누르면 분석 또는 내보내기를 즉시 중단할 수 있습니다.

## 웹UI 실시간 동기화
1. OCR 분석 결과 검토 다이얼로그에서 `웹분석` 버튼을 클릭하면 HTML 파일이 생성됩니다.
2. 생성된 HTML 파일을 웹 브라우저에서 열면 웹UI가 표시됩니다.
3. 웹UI와 데스크탑 애플리케이션이 WebSocket을 통해 실시간으로 동기화됩니다:
   - 데스크탑에서 편집(텍스트, 프레임, 병합, 삭제, 씬 분할)하면 웹UI에 자동 반영
   - 웹UI에서 편집(스마트 병합, undo/redo)하면 데스크탑에 자동 반영
4. 웹UI에서 편집한 내용을 JSON으로 내보낸 후, 데스크탑의 `웹에서 가져오기` 버튼으로 불러올 수 있습니다.

## 수정 사항 주석 (영상에 메모 남기기)
영상의 특정 장면에 “여기 고쳐주세요” 같은 내용을 **그림·글자**로 남기는 기능입니다. 메모는 영상 위에 직접 표시됩니다.

### 1. 준비
1. **Open Video A**로 동영상을 엽니다.
2. 사이드 컨트롤에서 **▶ 수정 사항 주석** 칸을 펼칩니다.
3. **주석 모드** 버튼을 켭니다. 켜진 동안에는 버튼이 빨간색으로 바뀌고, 영상 오른쪽 위에 **주석 모드** 배지가 보이며, 커서가 십자형이 됩니다 (버튼을 끄면 모두 원래대로).

### 2. 주석 그리기
- **도구**: 텍스트, 사각형, 타원, 선, 화살표 중 선택
- **색상**: 빨강·노랑 등 원하는 색 선택 — 도형도 글자도 고른 색 그대로 화면에 보이고 보내집니다 (1.6.1까지는 도형이 빨강 → 파랑처럼 R·B가 뒤바뀐 색으로 굽혔으므로, 그때 보낸 영상의 도형 색은 다시 보내야 맞습니다)
- **도형**: 영상 위에서 마우스로 드래그
- **텍스트**: 클릭한 뒤 나오는 창에 글 입력
- **표시 프레임 (시작~끝)**: 주석이 보일 프레임 범위 (시작=끝이면 한 프레임만)
- **텍스트 크기** / **선 굵기**: 숫자로 조절

### 3. 수정·삭제
- 그린 주석을 **클릭**하면 노란 점이 나옵니다. 드래그해서 **이동**·**크기 조절**이 가능합니다.
- **선택 주석 삭제**: 목록에서 고른 주석 하나만 삭제
- **현재 프레임에 보이는 주석 전체 삭제**: 지금 화면에 보이는 주석을 한 번에 삭제
- 목록에서 주석을 고르면 **표시 프레임** 숫자로 구간 수정 가능

### 4. 저장·보내기
- 주석은 **자동 저장**됩니다. 동영상 파일 옆 `.yesoncheck` 폴더에 JSON으로 저장됩니다.
- 같은 영상을 다시 열면 이전 주석이 **자동으로 불러와집니다**.
- **보내기 저장 폴더 선택** 후 **주석 포함 영상보내기**를 누르면, 주석이 영상에 박힌 새 파일이 만들어집니다.

### 팁
- 주석은 **프레임 구간**으로 표시됩니다 (예: 시작 10, 끝 50 → 10~50번 프레임에서 계속 보임).
- **OCR ROI 지정**과 **주석 모드**는 동시에 켤 수 없습니다.

## 이미지 시퀀스 재생 (Seq 탭)
렌더 폴더의 이미지 시퀀스(`EX01_01A_01_tk1-0001.tga`, `EX01_01A_01_tk1-0002.tga` …)를 영상처럼 열어 재생하고 비교합니다.

- **Mov / Seq / All 탭**: 사이드바 위의 **Mov**·**Seq**·**All** 탭으로 영상 목록과 시퀀스 목록을 오갑니다. 폴더 안의 시퀀스는 Seq 탭에
  `EX01_01A_01_tk1.seq`처럼 한 줄씩 보이고, 시퀀스만 있는 폴더를 열거나 끌어다 놓으면 Seq 탭으로 바로 넘어갑니다. Seq 탭에서는 선택 재생(Play Selected) 단추가 꺼집니다. Seq 목록에서도 위아래 화살표로 옮기면 그 시퀀스가 A에 열립니다.
- **All 탭**: 영상과 시퀀스를 **한 목록**에 이름 순서로 섞어 보여 줍니다 — 시퀀스 글자는 **하늘색**이라 영상과 한눈에 구분됩니다.
  항목을 누르면 종류대로 열리고, 우클릭 메뉴도 종류에 맞게 뜹니다. **선택 재생은 선택 중 mov만 이어서 재생**하고 시퀀스는
  건너뜁니다 (시퀀스 연속 재생은 메모리 한계). 우클릭 → **Mov만 모두 선택**으로 mov만 골라 전체 재생할 수 있습니다.
- **시퀀스로 인정하는 이름**: `<베이스>-NNNN.<확장자>` 파일이 2장 이상 (같은 베이스·확장자·자릿수). 확장자는 tga·png·jpg·jpeg·tif·tiff·exr.
  같은 폴더에 짝이 되는 `<베이스>.mov`(없으면 `.mp4`)가 있으면 그 영상의 fps를 쓰고(없으면 24fps), 번호가 빠진 프레임은 직전 프레임이 그대로 보입니다.
- **프레임 한 장으로 열기**: **Open Video A / Open Video B**로 `EX01_01A_01_tk1-0042.tga` 같은 프레임 파일 하나를 고르면 그 프레임이 속한 **시퀀스 전체**가 열립니다
  (고른 프레임이 아니라 첫 프레임부터). **영상 영역**에 프레임 파일을 끌어다 놓는 것도 영상 파일을 놓을 때처럼 열립니다 — 하나면 A, 서로 다른 시퀀스 둘이면 A·B,
  Seq 탭으로 넘어가 열린 시퀀스가 선택되고 그 폴더의 시퀀스들이 목록에 들어갑니다. **Mov 목록**에 놓으면 열지 않고 Seq 목록에만 넣습니다. 창의 나머지 부분(Seq 목록 위나 창 가장자리)에 놓는 것은 영상 영역에 놓는 것과 같게 동작합니다 (영상 파일·폴더도 마찬가지). 같은 이름의 프레임이 2장 미만인
  한 장뿐인 프레임은 시퀀스가 아니라서 예전처럼 한 장으로 열립니다 (끌어다 놓으면 무시). 영상 파일을 함께 놓으면 영상은 예전대로 열리고 시퀀스는 Seq 목록에만 더해집니다.
- **재생·주석**: 영상과 같은 재생 컨트롤(재생·프레임 이동·슬라이더)과 수정 사항 주석을 씁니다. 주석은 폴더의
  `.yesoncheck/<베이스>_seq_annotations.json`에 저장됩니다. OCR·씬 감지는 시퀀스에서 쓸 수 없습니다.
- **A/B 와이프**: 시퀀스끼리만 됩니다 (예: `_tk1` 대 `_tk2`). 영상과 시퀀스를 섞을 수는 없어서, 반대쪽과 종류가 다른 것을 열면 반대쪽이 닫히고 와이프가 꺼집니다.
- **썸네일**: 짝 `.mov`의 저장된 썸네일을 그대로 써서 이미지를 다시 읽지 않고 바로 보입니다 (짝 영상이 없을 때만 첫 프레임으로 만듭니다).
- **선택한 시퀀스로 MOV 만들기**: Seq 목록에서 시퀀스를 하나 이상 골라 우클릭 → **선택한 시퀀스로 MOV 만들기…** → 출력 폴더를 고르면
  `<베이스>.mov`(h264)가 만들어집니다. 출력은 **시퀀스가 있는 폴더가 아닌 다른 폴더**여야 하고(같은 폴더는 거부), 진행 창의 취소를 누르면 만들던 파일은 지워집니다.
  읽지 못한 프레임(깨진 파일·네트워크 끊김)은 직전 프레임으로 채워 길이는 그대로 만들고, 몇 개를 채웠는지 진행 창 로그에 항목마다·끝날 때 알려 줍니다(오류는 아님 — 납품 전에 원본 프레임을 확인하세요).

## 사이드바 — 개수와 다른 앱으로 열기
- **개수 줄**: 목록 바로 아래 한 줄에 지금 보는 탭의 개수가 보입니다 — Mov `12개`, Seq `시퀀스 3개`(프레임 수가 아니라 시퀀스 수),
  All `15개 — mov 10 · mp4 2 · tga 2 · exr 1`(포맷별 — 영상 포맷 먼저, 그다음 시퀀스의 프레임 형식, 각각 많은 순). 목록이 바뀌면 바로 따라 바뀝니다.
  - **종류·버전마다 나눔**: 이름 끝의 종류(`_HD`·`_OSAN`·`_TX`처럼 영문자뿐인 꼬리 — 없으면 `기본`)마다 세고, 그 안의 버전·테이크(`TK1`·`TK2`·`v001`·`v02`)를 괄호로
    보입니다 — 예: `450개 — 기본 225 (TK1 225) · HD 225 (TK1 225)`, `638개 — OSAN 615 (v01 397 · v02 176 · …) · TX 10 (v01 7 · v02 3) · …`, `189개 — 기본 189 (v001 189)`.
    All 탭은 첫 줄에 포맷, 둘째 줄에 종류(버전). 이름의 **끝에서만** 보므로 샷 코드(`V005` 등)를 버전으로 세지 않습니다.
- **QuickTime Player로 열기** (Mac): Mov·Seq·All 목록 우클릭 메뉴 맨 아래. 고른 영상을 QuickTime Player로 엽니다 — 시퀀스는 넘기지 않고,
  시퀀스만 골랐으면 꺼집니다. Windows에는 QuickTime Player가 없어(Apple이 Windows판 지원을 끝냄) 이 항목이 없습니다.
- **다른 앱으로 열기 ▸**: 등록한 앱으로 고른 것을 엽니다 — 영상은 그 파일, 시퀀스는 **첫 프레임 파일**(한 장을 받아 시퀀스로 알아보는 뷰어면 시퀀스 전체가 열립니다 — 앱마다 다르니 한 번 확인하세요).
  - **앱 등록…**: Mac은 `.app`, Windows는 `.exe`를 고릅니다. 여러 개 등록할 수 있고 등록한 차례로 보입니다. **앱 지우기 ▸**로 뺍니다.
  - 등록한 앱은 **이 PC에만** 저장됩니다(Mac `~/Library/Application Support/YesonCheck/prefs.json`, Windows `%LOCALAPPDATA%\YesonCheck\prefs.json`의 `open_with_apps`) — PC마다 앱 위치가 달라 공유 설정에는 넣지 않습니다.
  - 앱을 지웠거나 옮겼으면 메뉴에 `(찾을 수 없음)`으로 꺼진 채 보입니다 — 지우고 다시 등록하세요.
- 고른 것이 여러 개면 QuickTime Player에는 한 번에 넘기고, 등록한 앱은 **파일마다 따로** 띄웁니다(DJV처럼 한 번에 하나만 여는 앱이 있어서 — 파일마다 창이 하나씩). 20개를 넘으면 먼저 묻고, 지금 없는 파일이 있으면 열지 않고 어느 파일인지 알려 줍니다.

## 슬라이더 위 미리보기 (호버 썸네일)
시간 슬라이더(창 아래의 슬라이더와 V 모드 오버레이의 슬라이더) 위에 마우스 커서를 올리면 커서 위로 작은 창이 떠서 **그 자리 프레임의 그림과 프레임 번호**를 보여 줍니다(DJV의 타임라인 미리보기와 같은 방식). 커서를 움직이면 그림과 번호가 따라 바뀌어 **클릭하기 전에** 원하는 장면을 찾을 수 있습니다. 번호는 그 자리를 클릭했을 때 가는 프레임(Current와 같은 번호)입니다.

- 그림은 영상을 A로 연 뒤 **재생·탐색을 쉬는 동안 뒤에서** 만들어 메모리에 둡니다(이 Mac에서 쉴 때 4K 334장 약 38초 — 재생에 끼어들지 않게 CPU 하나로만 만듦). 재생하거나 슬라이더를 끌거나 프레임을 옮기는 동안에는 만들기를 멈춰 재생에 끼어들지 않고, 다시 쉬면 멈춘 자리부터 이어 만듭니다.
- 아직 만들지 않은 자리는 **번호와 빈 상자**만 보입니다. 500장이 넘는 긴 영상은 띄엄띄엄 만들어 가장 가까운 장면의 그림을 보입니다(번호는 정확).
- 지금 연 영상 하나 분만 메모리에 두고(다른 영상을 열면 버림) 디스크에는 저장하지 않습니다. 이미지 시퀀스(Seq)에는 아직 없습니다.
- **4GB가 넘는 파일**은 그림을 만들지 않고 번호만 보입니다(그림을 만들려면 파일 전체를 다시 읽어야 해서).
- 끄려면 메뉴 **Settings → 슬라이더 썸네일**의 체크를 풉니다(기본은 켬, **이 PC에만** 저장 — `prefs.json`의 `slider_thumbnails`). 이 창에는 바로, 이미 열려 있는 다른 창은 다음에 켤 때부터 적용됩니다. 끄면 그림을 만들지 않고 창도 뜨지 않습니다.
- 그림을 만들지 못하면 오류 창이 파일마다 한 번 뜹니다(재생·탐색은 그대로). 되풀이되면 Settings → 슬라이더 썸네일을 끄세요. 설정 파일이 깨져 있으면 켤 때 알림이 한 번 뜨고 그 세션은 꺼진 채로 시작합니다.

## ProRes 영상 빠른 재생 (자동)
ProRes mov는 **자동으로 더 빠른 디코더로 열립니다**. **Mac(Intel·Apple Silicon)** 은 Mac에 들어 있는 디코더(VideoToolbox)로 열고(아래 'Mac의 ProRes 재생'), **Windows**는 앱에 들어 있는 ffmpeg로 엽니다(아래 '(ffmpeg 방식)' 항목들). 주석 포함 영상보내기·병합·썸네일·씬 감지처럼 파일을 읽어 무언가를 만드는 기능은 어느 OS에서나 예전 그대로입니다(ffmpeg·OpenCV — Mac 디코더를 쓰지 않음). 재생이 끝날 때마다 앱 기록에 `[측정] … (fps)` 줄이 남으므로 속도는 그 줄로 확인합니다. 선택 재생(Play Selected)은 파일이 바뀔 때마다 `[측정] 전환 <초>초 (열기 <초>초) — <앞 파일> → <다음 파일>` 줄도 남습니다(앞 파일의 마지막 그림부터 다음 파일의 재생을 걸 때까지 — 실시간이면 0.04초 남짓). 영상을 열 때마다 `[측정] 열기 <초>초 — ffprobe … · 첫 프레임 … · 소리 … · 첫 화면 …` 줄로 여는 시간이 어디에 드는지도 남습니다. h264 같은 다른 형식은 예전과 똑같이 열립니다.

- **대상**: 프레임 속도가 일정하고 편집 목록·회전 정보가 없는 ProRes mov만입니다. 그 밖의 파일은 ProRes여도 예전 방식으로 엽니다.
- **프레임 번호는 예전과 같습니다** — 주석·구간의 프레임 번호가 다른 PC·예전 버전과 어긋나지 않습니다.
- **색**: 앱은 파일의 값을 모니터에 맞춘 변환 없이 그대로 그립니다. QuickTime Player는 파일의 색 태그와 모니터 프로파일에 맞춰 변환해 보여 주므로 **앱 화면이 QuickTime과 다르게 보일 수 있습니다** (차이는 파일의 태그와 모니터에 따라 다릅니다). Mac 재생은 Windows 재생, 그리고 내보내기(ffmpeg — Mac 포함)와 색이 급변하는 가장자리 1픽셀에서 아주 미세하게 다를 수 있습니다 (ProRes 422처럼 색 정보를 줄여 담은 파일에서 — 두 디코더가 빠진 색을 채우는 방식이 달라서이고, 화면 전체로는 보이지 않습니다). 색 정보(bt709 등)가 적히지 않은 HD 파일은 Mac에서 bt709로 읽으므로 ffmpeg 방식과는 화면 전체의 색이 조금 다를 수 있습니다. 그래서 Mac 화면은 이전 버전의 Mac 화면과도 이 두 가지만큼 다를 수 있습니다.
- **ffmpeg 방식으로 열렸는지**는 앱 기록(터미널·로그 파일)의 `[재생] ffmpeg 파이프: …` 줄로 압니다 (Mac의 VideoToolbox는 아래 'Mac의 ProRes 재생').
- **(ffmpeg 방식) 멈춰 두면 영상 전체를 메모리에 읽어 두어, 그 뒤 되감기·탐색이 바로 됩니다**: Windows, 그리고 Mac에서 ffmpeg 방식으로 연 영상(아래 '재생 디코더 바꾸기'에서 ffmpeg를 골랐거나 HDR ProRes)은 재생·탐색을 멈추고 0.3초가 지나면 쉬는 동안 영상 전체를 처음부터 메모리에 읽어 둡니다
  (4K 13.9초 영상은 약 7초, 1080p는 약 2초 — 다른 무거운 작업이 없을 때). 다 읽은 뒤에는 어디로든 되감기·←·슬라이더 끌기·반복 재생(`Loop Play`)이 기다림 없이 바로 보입니다.
  재생하는 동안에는 읽어 두기를 멈추므로(A/B를 열고 한쪽만 재생하는 동안 다른 쪽도 멈춤) 처음 재생이 느려지지 않고, 아직 읽어 두지 않은 구간은 예전처럼 잠깐(4K는 약 0.5초) 걸릴 수 있습니다. 재생 속도 자체는 그대로입니다.
  다 읽으면 앱 기록에 `[파이프] 프레임 캐시 채움 끝: …` 줄이 남고, 읽어 두기가 실패하면 `[파이프] 프레임 캐시 채움을 멈췄습니다 — …` 줄만 남기고 재생·탐색은 예전처럼 계속됩니다 (오류 창은 뜨지 않음).
  아직 읽어 두지 않은 구간에서 ←로 뒤로 갈 때는 8번에 한 번만 잠깐(4K는 약 0.6초) 멈추고 나머지는 바로 나옵니다 (뒤로 갈 때 그 앞 8프레임을 함께 읽어 둡니다 — 최근 8프레임만 두는 방식에서도 같음). 앞으로 건너뛰는 것은 예전과 같습니다.
  - 메모리를 꽤 씁니다 — 4K 13.9초 영상(334프레임)을 다 읽어 두면 약 **8.3GB**, A/B 와이프에 4K를 둘 열면 약 16.6GB (1080p는 같은 길이에 약 2.1GB). 영상을 닫거나 다른 영상을 열면 바로 돌아옵니다.
  - 창 하나에서 PC 메모리의 20%까지만(그 창의 A/B 둘을 합쳐) 이렇게 쓰고, 영상이 그보다 크거나 지금 쓸 수 있는 메모리가 모자라면 그 영상은 **예전처럼 최근 8프레임만** 둡니다 (4K는 영상 하나당 약 370MB, 둘이면 약 750MB).
    예: 메모리 32GB PC에서 4K는 예전 방식, 1080p는 읽어 둔 뒤 바로. 어느 쪽인지는 앱 기록의 `[파이프] 프레임 캐시: 전체 …`(메모리에 둠) 또는 `[파이프] 프레임 캐시: 링 8장 — …`(예전 방식 — 뒤에 이유) 줄로 압니다.
  - 20%는 **창마다** 따로 셉니다 — 창 하나가 앱 하나라(Finder에서 영상 여러 개를 한꺼번에 열면 창이 여러 개 뜸) 여러 창은 서로가 쓰는 몫을 보지 못합니다. 창을 여러 개 띄워 저마다 4K를 열어 두면(멈춰 두면 저절로 다 읽음) 그만큼 메모리를 더 쓰니, 메모리가 빠듯하면 다 본 창은 닫아 주세요.
- **문제가 있으면**: 환경 변수 `YESONCHECK_MOVIE_SOURCE=cv2`를 정하고 앱을 다시 켜면 예전 방식으로 돌아갑니다 (Mac의 VideoToolbox·ffmpeg 방식 모두 쓰지 않음 — 예: 개발 모드는 `YESONCHECK_MOVIE_SOURCE=cv2 ./run_app.sh`). 기본은 `auto`이고, `auto`·`pipe`·`cv2` 외의 값은 켤 때 오류로 알립니다.
  - **Windows(설치한 앱)**: 설정 → 시스템 → 정보 → 고급 시스템 설정 → 환경 변수 → 사용자 변수에서 **새로 만들기** — 이름 `YESONCHECK_MOVIE_SOURCE`, 값 `cv2`. 또는 명령 프롬프트에서 `setx YESONCHECK_MOVIE_SOURCE cv2`. 앱을 다시 켜야 적용됩니다 (되돌리려면 그 변수를 지우고 앱을 다시 켭니다).
  - Windows에서 보안 프로그램이 앱 안의 로컬 통신(127.0.0.1 루프백 TCP)을 막으면 ProRes 영상 열기가 실패합니다 — 이때 이 설정이 탈출구입니다 (오류 창 끝 줄에도 안내가 나옵니다).
- **(ffmpeg 방식) 메모리에 두는 것만 끄려면**(빠른 디코더는 그대로, 되감기·탐색은 예전처럼 최근 8프레임만): 환경 변수 `YESONCHECK_FRAME_CACHE=ring`을 정하고 앱을 다시 켭니다 (예: 개발 모드는 `YESONCHECK_FRAME_CACHE=ring ./run_app.sh`).
  기본은 `auto`이고, `auto`·`ring` 외의 값은 켤 때 오류로 알립니다. Windows는 위와 같은 방법으로 이름 `YESONCHECK_FRAME_CACHE`, 값 `ring` (또는 `setx YESONCHECK_FRAME_CACHE ring`) — 되돌리려면 그 변수를 지우고 앱을 다시 켭니다.
  이렇게 끄면 앱 기록에 `[파이프] 프레임 캐시:` 줄이 아예 나오지 않습니다 (`[재생] ffmpeg 파이프: …` 줄은 그대로).
- **Mac에서 영상 화면이 이상하면**: 영상 영역이 비어 있거나 '영상 화면(GL 텍스처 스트리밍)을 그리지 못했습니다' 오류 창이 뜨면, 환경 변수 `YESONCHECK_VIDEO_ITEM=pixmap`을 정하고 앱을 다시 켜면 예전 그리기 방식으로 돌아갑니다 (예: 개발 모드는 `YESONCHECK_VIDEO_ITEM=pixmap ./run_app.sh`, 빌드한 앱은 터미널에서 `YESONCHECK_VIDEO_ITEM=pixmap "<앱 위치>/YesonCheck_Autocut_Intel.app/Contents/MacOS/YesonCheck_Autocut"`처럼 앱 안의 실행 파일을 직접 켭니다 — Apple Silicon 앱은 `_AppleSilicon.app`). 기본은 `auto`이고, `auto`·`gl`·`pixmap` 외의 값은 켤 때 오류로 알립니다. 새 방식으로 그리는지는 앱 기록의 `[표시] GL 텍스처 스트리밍(VideoFrameItem)` 줄로 압니다. Windows는 화면 그리기가 예전 그대로라 해당 없습니다.
- **재생 중 디코더가 끊기면** 오류 창이 한 번 뜨고 영상이 끝난 것처럼 멈춥니다 — 같은 영상을 다시 열면 됩니다.
- 4K ProRes 4444는 초당 약 130MB(≈1Gbps)를 읽어야 해서, 1Gbps(기가비트) 네트워크에서는 처음 재생이 끊길 수 있습니다 (한 번 읽은 뒤에는 캐시 덕에 부드럽습니다).

### Mac의 ProRes 재생
Mac(Intel·Apple Silicon)에서는 ProRes가 **Mac에 들어 있는 디코더(VideoToolbox)로 열려** 화면까지 곧바로 갑니다 — 디코드한 그림을 복사하지 않고 GPU가 그대로 그립니다. 화면 색은 QuickTime Player와 다를 수 있습니다(위 '색'). A/B 와이프로 두 영상을 함께 재생하면 디코더가 두 배로 일하므로 큰 영상(4K)은 느려질 수 있습니다(되는 만큼만 — 하드웨어의 한계).

- **대상**: 위 '대상'의 ProRes 중 HDR(PQ·HLG 또는 BT.2020 색)이 아닌 파일 전부 — 해상도(1080p·4K), 프로파일(422·422 HQ·4444·알파), 색 정보가 적혔는지와 상관없습니다. HDR ProRes는 톤 매핑을 하지 않으므로 ffmpeg 방식으로 엽니다. h264 같은 다른 형식은 예전 그대로이고, **Windows는 바뀐 것이 없습니다**.
- **이 방식으로 열렸는지**는 앱 기록으로 압니다: 켤 때 `[재생] 디코더: videotoolbox (기본값)` 한 줄(설정을 바꿨으면 `(prefs.json)`), 파일을 열 때마다 `[재생] 네이티브(VideoToolbox): <파일> (…)` 줄. 대상이 아닌 파일은 `[재생] 네이티브(VideoToolbox): 아님 — <이유>: <파일>` 다음 줄에 ffmpeg 방식의 줄이 나옵니다. 재생이 끝나면 `[측정] <장 수>장 <초>초 (<fps>fps) 네이티브=yes …` 한 줄이 남습니다.
- **프레임 번호·색**: 프레임 번호는 예전과 같습니다. 색은 위의 '색'.
- **메모리**: 영상 전체를 메모리에 읽어 두지 않습니다(위의 '(ffmpeg 방식) 멈춰 두면 영상 전체를 메모리에…'와 `YESONCHECK_FRAME_CACHE`는 해당 없음) — 최근 8프레임만 두고, 그 밖으로 가면 그 자리부터 다시 읽습니다.
- **B 키 글자와 주석**: 영상에 굽지 않고 영상 위에 겹쳐 그립니다. 크기·자리는 같게 맞췄지만 B 키 글자의 글꼴과 주석 선의 모양이 조금 다르게 보이고, 와이프를 켜면 A의 B 키 글자·주석이 와이프 선에서 잘리지 않고 B 쪽까지 보입니다. '주석 포함 영상보내기'는 예전처럼 영상에 굽습니다.
- **재생 디코더 바꾸기 (예비)**: 메뉴 **Settings → 재생 디코더 (Mac)** 에서 `VideoToolbox (기본)` 또는 `ffmpeg (예전 방식)`을 고릅니다. 고른 값은 **이 Mac에만** 저장되고(다른 PC·NAS 설정과 무관), **바로 적용됩니다** — 보던 영상을 같은 프레임에서 그 디코더로 다시 열고, 재생 중이었으면 이어서 재생합니다(앱을 다시 켜지 않음, 와이프·주석·OCR 결과·줌은 그대로). 이미 열려 있는 **다른 창은 다음에 켤 때부터** 따릅니다. Windows에는 이 메뉴가 없습니다. ffmpeg로 바꿀 때는 영상을 다시 여는 동안 화면이 잠깐 멈출 수 있습니다.
- **진단용 환경 변수**: `YESONCHECK_MAC_NATIVE=off`(또는 `on`)를 정하고 켜면 그 실행에서는 위 메뉴의 설정을 덮습니다(메뉴의 두 항목이 회색이 되고 툴팁에 이유 — 예: 개발 모드는 `YESONCHECK_MAC_NATIVE=off ./run_app.sh`). 기본은 `auto`(메뉴의 설정을 따름)이고, `auto`·`on`·`off` 외의 값은 켤 때 오류로 알립니다. 위의 `YESONCHECK_MOVIE_SOURCE=cv2`를 정하면 이 방식도 쓰지 않습니다(전부 예전 방식 — 메뉴도 회색).
- 위의 `YESONCHECK_VIDEO_ITEM=pixmap`(예전 그리기 방식)을 정한 채 이 방식으로 연 영상에서 와이프를 켜면 **A만 보입니다**(와이프 선은 보이지만 B를 그리지 않음) — 그때 와이프가 필요하면 Settings → 재생 디코더 (Mac)에서 `ffmpeg (예전 방식)`을 고르세요.
- 이 방식으로 열지 못한 파일은 '영상을 열 수 없음(네이티브)' 오류 창이 한 번 뜬 뒤 ffmpeg 방식으로 이어서 열립니다 (아래 '트러블슈팅').
- 이 Mac의 그래픽에서 이 방식의 화면을 그리지 못하면 '네이티브 화면 그리기에 실패해 이 창은 ffmpeg 방식으로 바꿉니다…' 오류 창이 한 번 뜨고, **그 창은 ffmpeg 방식으로 계속 재생**합니다(설정은 그대로라 **다음에 켜는 창은 다시 이 방식을 시도**합니다). 창마다 되풀이되면 Settings → 재생 디코더 (Mac)에서 `ffmpeg (예전 방식)`을 고르세요.

## Windows의 화면 그리기 (CPU·GPU)

Windows에서 4K 재생이 끊기면 **Settings → 화면 그리기 (Windows) → GPU**를 골라 보세요. 다음에 여는 창부터 그래픽 카드로 화면을 그립니다. 기본은 **CPU**(예전 그대로)입니다.

- 이 PC의 그래픽 드라이버가 맞지 않으면(ANGLE, 소프트웨어 OpenGL, 원격 접속 등) 알림을 보이고 CPU로 계속합니다.
- 메뉴의 `지금 이 창:` 줄에서 이 창이 실제로 어느 쪽으로 그리는지 볼 수 있습니다.
- GPU를 고른 뒤 앱이 켜지지 않으면 `%LOCALAPPDATA%\YesonCheck\prefs.json`에서 `display_renderer` 줄을 지우거나, 명령 프롬프트에서 `set YESONCHECK_VIEWPORT=raster`로 설정한 뒤 그 창에서 앱을 켜면 CPU로 열립니다.
- 재생이 끝날 때마다 앱 기록의 `[측정]` 줄에 평균 fps와 함께 가장 긴 프레임 간격과 끊긴 횟수가 남으므로, 두 방식을 숫자로 비교할 수 있습니다.

## 북마크 (폴더 즐겨찾기)
자주 여는 폴더를 북마크에 두고 바로 엽니다. 북마크는 이 PC의 사용자별 파일(`~/.yeson_bookmarks.json`)에 저장되고, 창을 여러 개 띄워도 서로의 것을 잃지 않습니다.

- **더하기**: 사이드바의 **Add Bookmark**로 폴더를 고르거나, 폴더를 창에 끌어다 놓으면 저절로 더해집니다.
- **관리 창**: **Bookmarks** 단추 또는 **P 키**(한글 자판 **ㅔ**). 항목을 **더블클릭**(또는 **Enter**·**폴더 열기**)하면 그 폴더의 영상 목록을 엽니다.
- **경로 고치기** (DJV와 같은 방식): 고른 항목을 **한 번 더 클릭**하거나 우클릭 → **경로 수정**을 누르면 경로를 그 자리에서 고칠 수 있습니다 —
  예: `…/GASA01/scene-01A_S03/frames`를 `…/GASA01/scene-01A_S04/frames`로. **Enter**로 마치면(창 안의 다른 곳을 클릭하거나 창을 닫아도) 고친 경로가
  **바로 저장**되어 **폴더 열기**와 다음에 창을 열 때 모두 고친 경로를 씁니다. **Esc**는 취소. 고치는 중에 Finder 등 다른 앱에 갔다 와도 편집 중인 글은
  그대로라 경로를 복사해 와서 붙여 넣을 수 있습니다. 앞뒤 공백·따옴표·`~`·끝의 `/`는 정리해 저장하고, 처음부터 적지 않은 경로(`clips`)는 받지 않습니다. 고치던 중에 **폴더 열기**를 누르면 고친 경로를 엽니다.
  이미 북마크에 있는 경로로 고치면 되돌리고 알려 주며, 지금 없는 폴더(오타·연결되지 않은 공유)로 고치면 저장은 하되 경고가 뜹니다.
- **우클릭 메뉴**: **경로 복사**(클립보드에)·**경로 수정**·**폴더 열기**·**삭제**.

## 창 여러 개 열기와 동영상 열기
YesonCheck는 **창 하나가 앱 하나**입니다. 창을 더 열면 앱이 하나 더 뜨고, 이미 열려 있는 창은 그대로(닫히지도, 앞으로
오지도 않음) 남습니다 — 영상을 여러 개 띄워 놓고 검토할 수 있습니다. 이미 다른 창에 열려 있는 영상을 다시 열어도 새 창입니다.

### Mac에서 창 더 열기
- 응용 프로그램 폴더·Launchpad·Spotlight에서 YesonCheck를 **다시 실행**하거나 **Dock의 YesonCheck 아이콘을 누르면**
  빈 새 창이 하나 뜹니다.
- ⌘Tab, 열려 있는 창 클릭, Mission Control 같은 평범한 전환으로는 새 창이 뜨지 않습니다.
- Dock으로 내려 둔(최소화한) 창은 Dock 아이콘을 눌러도 올라오지 않고 내려간 채로 있습니다 — 새 창만 뜹니다. 내려 둔 창은
  Dock 오른쪽의 그 창 아이콘을 눌러 올리세요. 시스템 설정의 **윈도우를 응용 프로그램 아이콘으로 최소화**를 켜 두었다면 창
  아이콘이 따로 생기지 않으므로, Dock의 YesonCheck 아이콘을 **우클릭**해 나오는 창 목록에서 그 창을 고르세요 (YesonCheck
  아이콘이 여럿이면 그 창의 아이콘).
- Dock에는 창(앱)마다 YesonCheck 아이콘이 하나씩 보일 수 있습니다.
- 알아 둘 점: 이미 맨 앞에 있는 YesonCheck의 Dock 아이콘을 누르면 예전에는 사이드바 목록을 다시 읽었지만 이제는 새
  창이 뜹니다. 다른 앱에서 YesonCheck로 돌아올 때의 다시 읽기는 그대로이고, 새로고침 버튼(F5)으로도 읽을 수 있습니다.
- 창을 닫는 중(작업을 마무리하느라 최대 약 30초 걸릴 수 있음)에 Dock 아이콘을 누르거나 앱을 다시 실행하면 새 창이 뜨지
  않습니다. 그동안 Finder에서 영상을 더블클릭하거나 **다음으로 열기**로 열어도 macOS가 닫히는 그 창으로 보내 **열리지 않고
  아무 알림도 없을 수 있습니다** — 그 창이 완전히 닫힌 뒤 다시 여세요.

### 동영상 열기 (.mov·.mp4)
- Finder(탐색기)에서 영상을 **더블클릭**하거나 우클릭 → **다음으로 열기**(Windows는 **연결 프로그램**)에서 YesonCheck를
  고르면 새 창의 **영상 A**에 열립니다. YesonCheck가 꺼져 있었다면 앱이 켜지며 그 영상을 A에 엽니다.
- 영상을 **여러 개 골라 한꺼번에** 열면 **영상마다 창 하나**입니다 (YesonCheck가 꺼져 있었다면 첫 영상은 처음 켜지는 창,
  나머지는 새 창).
- 새 창을 띄우지 못하면 오류 창에 이유가 보이고, 지금 창은 그대로입니다.
- 영상을 열지 못하면(파일이 없어졌거나, NAS 연결이 끊겼거나, 읽을 수 없는 파일) 오류 창에 그 영상의 경로와 이유가 보이고 창은
  그대로 남습니다. (Mac에서 NAS의 한글 이름 폴더에 있는 영상은 macOS가 넘긴 이름의 한글 표기가 저장된 것과 달라도 찾아서 엽니다.)

### Mac — 동영상을 더블클릭하면 YesonCheck로 열기 (기본 앱)
- 앱은 `.mov`·`.mp4`를 열 수 있다고 macOS에 알려 두므로 **다음으로 열기** 목록에는 늘 YesonCheck가 보입니다. 설치했다고
  기본 앱이 저절로 바뀌지는 않습니다.
- 새 버전을 **처음 켤 때 한 번**, 두 종류 중 기본 앱이 YesonCheck가 아닌 것이 있으면 "동영상(.mov·.mp4)을 더블클릭하면
  YesonCheck로 열까요?"라고 묻습니다. [예]면 두 종류의 기본 앱을 YesonCheck로 정하고(macOS가 확인 창을 더 띄우면 그대로
  답하세요), [아니요]면 다시 묻지 않습니다.
  - 단추를 누르지 않고 창만 닫으면(Esc·⌘.) 답한 것으로 치지 않아 **다음에 켤 때 다시 묻습니다.** 다른 창의 업데이트가 이
    질문 창을 닫은 경우도 같습니다.
  - 업데이트 직후 다시 켜진 앱은 묻지 않고, 그다음에 보통으로 켤 때 묻습니다.
  - 다른 YesonCheck 창이 이미 열려 있으면 묻지 않습니다 — 영상을 여러 개 한꺼번에 열거나 Dock을 눌러 창을 여러 개 띄워도 질문은
    처음 창에만 뜹니다. 그 질문을 답하지 않고 닫았다면 다른 창 없이 YesonCheck를 켤 때 다시 묻습니다.
  - 디스크 이미지(dmg)나 다른 디스크(`/Volumes`)에서 바로 연 앱, macOS가 임시 위치에서 격리해 실행 중인 앱에서는 묻지도
    정하지도 않습니다(Help 메뉴에서는 이유를 알려 줍니다) — 앱을 응용 프로그램 폴더로 옮긴 뒤 거기서 다시 여세요.
- 마음이 바뀌었거나 [아니요]를 눌렀다면 **Help → 동영상 기본 앱으로 정하기…**를 누르세요. 묻지 않고 바로 정하고
  "동영상(.mov·.mp4)을 더블클릭하면 YesonCheck로 열립니다."가 보입니다.
- Mac에 같은 앱 ID의 다른 YesonCheck(예: 예전에 받아 둔 사본)가 더 있으면 동영상을 더블클릭할 때 macOS가 그중 하나를
  열 수 있습니다. 기본 앱으로 정한 뒤 그런 사본의 경로를 창에 보여 줍니다 — 쓰지 않는 사본은 직접 지워 주세요
  (YesonCheck는 아무것도 지우지 않습니다).

### Windows — 동영상 연결 프로그램
- Windows 10·11은 설치 프로그램이나 앱이 기본 앱을 마음대로 바꾸지 못하게 합니다. 그래서 설치 프로그램이 **이 계정**에
  YesonCheck를 `.mov`·`.mp4`를 여는 앱으로 **등록**해 두고(관리자 권한 필요 없음), 기본 앱은 사용자가 한 번 고릅니다.
- 영상을 우클릭 → **연결 프로그램**(또는 **다른 앱 선택**)에서 **Yeson Checker**를 고르고 **항상**을 누르세요(.mov·.mp4
  각각 한 번). 그 뒤 더블클릭이 YesonCheck로 열립니다.
- 앱의 **Help → 동영상 기본 앱 설정 열기…**를 누르면 Windows 기본 앱 설정 화면이 열립니다 (최신 Windows 11은 YesonCheck
  항목으로 바로, Windows 10과 예전 Windows 11은 기본 앱 화면에서 직접 찾아야 합니다).
- 같은 PC의 다른 Windows 계정은 그 계정에서 YesonCheck를 처음 켤 때 앱이 같은 등록을 합니다.
- 알아 둘 점:
  - 제거하면 제거하는 계정의 등록만 지워집니다. 같은 PC의 다른 계정에는 앱이 등록한 항목이 남아 "연결 프로그램"에 없어진
    YesonCheck가 보일 수 있습니다. 그 항목은 지워진 프로그램을 가리키므로, 고르면 Windows가 앱을 찾을 수 없다고 알리고 다른
    앱을 고르게 합니다. 그 계정에서 YesonCheck를 다시 설치하거나 켜면 항목이 새로 고쳐집니다.
  - 설치하지 않은 복사본(폴더째 복사한 빌드 등)을 켜면 그 계정의 "연결 프로그램" 항목이 그 복사본을 가리키도록 바뀝니다.
    설치한 YesonCheck를 다시 켜면 설치한 쪽으로 돌아옵니다.

## 버전과 자동 업데이트
창 제목과 Help → 정보에서 지금 버전을 볼 수 있습니다(예: `1.1.0`, 소스에서 바로 실행하면 "개발(소스)").
1.1.0부터는 새 버전이 나오면 창 위 알림 띠로 알리고 [업데이트]를 누르면 받아서 설치한 뒤 다시 켜집니다 —
실패하면 지금 버전이 그대로 유지됩니다. 배포 절차와 손으로 설치하는 방법은 [BUILD.md](BUILD.md)를 참고하세요.

### 창을 여러 개 띄워 둔 채 업데이트할 때
- [업데이트]를 누르면 다른 YesonCheck 창을 먼저 확인하고 **한 번만** 묻습니다: "다른 YesonCheck 창 n개도 닫힙니다."
  [모두 닫고 업데이트]를 누르면 받은 뒤 다른 창들은 닫기 버튼을 누른 것처럼 **정상적으로 닫히고**, 누른 창 하나만 새
  버전으로 다시 켜집니다. [취소]면 아무것도 바뀌지 않습니다.
- OCR 분석·내보내기·병합 등 **작업 중인 창**이 있으면 확인 창에 그 창과 작업이 보이고, 계속하면 그 작업은 멈춥니다.
- OCR·애니매틱 검토에서 **저장하지 않은 결과**가 있는 창도 확인 창에 보입니다 — 계속하면 그 결과는 사라집니다.
  지키려면 [취소]하고 그 창에서 저장한 뒤 다시 [업데이트]를 누르세요.
- 닫히지 않는 창이 있으면 업데이트를 멈추고 "업데이트를 멈췄습니다 — 이 창이 닫히지 않았습니다: …"로 알립니다. 지금

## 주요 기능
- **OCR 분석**: PaddleOCR을 사용한 텍스트 인식 및 구간 추출
- **애니매틱 모드**: PySceneDetect를 사용한 자동 씬 컷 감지
- **애니매틱2 모드**: TransNetV2(TensorFlow)를 사용한 컷 감지 (디졸브·페이드 포함, Mac·Windows 빌드에 포함)
- **웹UI 실시간 동기화**: WebSocket을 통한 데스크탑-웹 양방향 동기화
- **씬 편집**: 병합, 삭제, 씬 분할, 스마트 병합, undo/redo
- **우클릭 컨텍스트 메뉴**: 타임라인 및 테이블에서 우클릭으로 모든 편집 기능 접근 (데스크탑 및 웹UI)
- **내보내기**: 전체 내보내기, 선택한 항목만 내보내기, 사운드 포함 옵션
- **썸네일 최적화**: 프리로드 및 저장된 썸네일 재사용으로 빠른 로딩
- **프리뷰 재생**: 종료 프레임까지 정확한 재생 보장
- **수정 사항 주석**: 프레임별 텍스트·도형 주석, 자동 저장, 주석 포함 영상보내기
- **이미지 시퀀스**: tga·png·exr 등 프레임 시퀀스 재생·A/B 와이프, 선택한 시퀀스로 MOV 만들기 (Seq 탭)
- **재생 FPS 표시**: 정보 줄의 `재생: 24 FPS · 실제 23.8` — 뒤의 '실제'가 재생 중 실제로 진행한 fps라 리얼타임 재생인지 바로 보입니다(원래 fps에 한참 못 미치면 느린 것; 1초마다 재는 값이라 ±1 정도 흔들리고 조금 높게도 나옵니다)
- **B 키 오버레이**: 영상에 굽는 파일 이름·프레임 번호 글자가 창에 맞춰 볼 때 해상도와 상관없이 같은 크기로 보입니다(1080p 기준 예전의 1.5배, 4K도 같은 크기·같은 굵기 — 예전엔 4K에서 반 크기; 1:1 줌에서는 4K 글자가 2배)
- **미디어 정보**: 사이드바 우클릭 → 미디어 정보에 코덱 프로파일·태그(예 Apple ProRes 4444 · ap4h), 픽셀 형식(4:4:4 · 12비트 · 알파), 색 공간·범위, 비트레이트, 음성 트랙, 컨테이너·파일 크기까지 보이고, '자세히'에 ffprobe 원본이 있습니다 (길이는 영상 트랙 길이)
- **사이드바 개수·다른 앱으로 열기**: 목록 아래 개수 줄(All은 포맷별), 우클릭 → QuickTime Player로 열기(Mac)·다른 앱으로 열기(등록한 앱 — 시퀀스는 첫 프레임) (위 '사이드바 — 개수와 다른 앱으로 열기')
- **북마크**: 폴더 즐겨찾기 — 관리 창(**P** 키)에서 경로를 클릭해 그 자리에서 고치면 바로 반영, 우클릭으로 경로 복사 (아래 '북마크')
- **ProRes 빠른 재생**: Mac(Intel·Apple Silicon)은 ProRes(HDR 제외)를 Mac의 디코더(VideoToolbox)로 열어 GPU에 곧바로 그림, Windows는 앱에 들어 있는 ffmpeg로 — 속도는 재생이 끝날 때마다 앱 기록의 `[측정]` 줄 (위 'ProRes 영상 빠른 재생')
- **재생 디코더 (Mac)**: Settings → 재생 디코더 (Mac)에서 `VideoToolbox (기본)`·`ffmpeg (예전 방식)` — 이 Mac에만 저장, 고르면 보던 영상에 바로 적용 (위 'Mac의 ProRes 재생')
- **슬라이더 호버 썸네일**: 슬라이더 위에 커서를 올리면 그 프레임의 그림과 번호 — 쉬는 동안 뒤에서 만들고, 끄기는 Settings → 슬라이더 썸네일 (위 '슬라이더 위 미리보기')

## 트러블슈팅
- **`ModuleNotFoundError: No module named 'cv2'`**  
  가상환경이 올바르게 활성화되었는지 확인하세요. 환경이 깨졌다면 `~/coding/p310_tf`를 지우고 `./setup_build_env.sh`로 다시 만드세요.
- **FFmpeg 관련 오류**  
  개발 모드(`run_app.sh`)는 PATH의 `ffmpeg`·`ffprobe`를 씁니다(`brew install ffmpeg`). 빌드된 앱은 번들 안의 정적 ffmpeg를 씁니다.

- **'영상을 열 수 없음(네이티브)' 창이 뜸 (Mac)**  
  ProRes를 Mac의 디코더(VideoToolbox)로 열지 못했다는 알림입니다. 창을 닫으면 앱이 ffmpeg 방식으로 이어서 엽니다. 같은 일이 되풀이되면 Settings → 재생 디코더 (Mac)에서 `ffmpeg (예전 방식)`을 고르세요 (위 'Mac의 ProRes 재생' — 창 끝 줄의 환경 변수 `YESONCHECK_MAC_NATIVE=off`도 같은 효과). 재생 도중에 끊기면 'VideoToolbox로 영상을 읽다가 도중에 실패해 …' 오류 창이 한 번 뜨고 영상이 끝난 것처럼 멈춥니다 — 같은 영상을 다시 열면 됩니다.
- **'네이티브 화면 그리기에 실패해 이 창은 ffmpeg 방식으로 바꿉니다' 창이 뜸 (Mac)**  
  이 Mac의 그래픽이 Mac 디코더의 그림을 그리지 못했다는 알림입니다. 그 창은 곧바로 ffmpeg 방식으로 바꿔 계속 재생하고, 다음에 켜는 창은 다시 Mac 디코더를 시도합니다. 창마다 되풀이되면 Settings → 재생 디코더 (Mac)에서 `ffmpeg (예전 방식)`을 고르세요.

- **Windows에서 화면은 나오는데 소리가 나지 않음**  
  그 PC에 K-Lite Codec Pack(Basic)이 설치되어 있는지 확인하세요(위 '준비 사항'). 앱 기록(`%LOCALAPPDATA%\YesonCheck\logs`)에 소리 재생기의 상태가 남습니다 — `[소리] 상태: 열 수 없음(InvalidMedia)`·`[소리] 재생기 오류: …`·`[Qt 경고] …` 줄이면 파일의 소리를 열지 못한 것이고, `[소리] 소리 트랙: 없음`이면 그 파일에 소리가 없는 것입니다(ProRes 렌더 파일은 대부분 소리가 없음). 환경 변수 `QT_MULTIMEDIA_PREFERRED_PLUGINS`를 설정해 두었다면 지우세요 — 앱이 K-Lite를 쓰지 않게 됩니다.
